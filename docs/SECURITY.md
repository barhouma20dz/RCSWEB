## 2) الثغرات المكتشفة والإصلاحات

### 🔴 حرجة — تم الإصلاح

#### V1: انتحال حسابات كاملة عبر تزوير التوكن (B1/B2/B3)
- **الوصف**: كان مفتاح توقيع الجلسات قيمة ثابتة معروفة داخل الكود (`raed-saida-club-secret-key-2024`).
  أي شخص يقرأ الكود يستطيع توليد توكن "مدير عام" صالح بالكامل — **بدون كلمة مرور** — والدخول لكل بيانات
  النادي: طلبات الانخراط، أرقام هواتف المنخرطين وأولياء الأمور، حسابات الفروع، كتب النادي.
- **إثبات الاختراق**: توكن مزوّر بمعرّف حساب حقيقي أعاد `HTTP 200` من `/api/admin/data` بكامل البيانات.
- **الإصلاح**:
  - مفتاح سري عشوائي 64 خانة ست عشرية يُولَّد خارج الكود ويُحمَّل من `.env` (`AUTH_SECRET`)
  - **إغلاق آمن (fail-closed)**: غياب المفتاح يوقف التشغيل فوراً بدل السقوط لقيمة افتراضية
  - التحقق أُعيد بناؤه بحيث لا يُقبل أي توكن إلا بتوقيع المفتاح الحقيقي → التزوير أصبح مستحيلاً رياضياً
    (توقيع HMAC-SHA256 بمفتاح 256-بت عشوائي)

#### V2: تلف التوكن بعد تسريب سابق (إبطال الجلسات)
- **الوصف**: بما أن المفتاح القديم كان معروفاً ومحفوظاً في تاريخ الكود، أي توكن صدر سابقاً ظل صالحاً أسبوعاً كاملاً
  ولم تكن هناك آلية لإبطاله.
- **الإصلاح**: كل حساب (إدارة/مكتب) يحمل الآن حقل `tokenInvalidBefore` — كل توكن صدر قبل لحظة تغيير كلمة المرور
  يُرفض فوراً. **تغيير كلمة المرور = تسجيل خروج إجباري لكل الأجهزة الأخرى لحظياً.**

### 🟠 عالية — تم الإصلاح

#### V3: القوة الغاشمة على تسجيل الدخول (D1)
- **الوصف**: 15 محاولة كلمة مرور خاطئة متتالية قُبلت كلها بدون أي حد — يمكن تخمين كلمات المرور آلاف المرات
  في الدقيقة، والخادم يستهلك موارد ثقيلة (scrypt) مع كل محاولة → ثغرة إغراق معالج أيضاً.
- **الإصلاح** (طبقتان):
  1. **قفل الحساب**: بعد 5 إخفاقات لاسم مستخدم واحد من نفس العنوان → حجب 10 دقائق (`429 Retry-After`)
  2. **حد العنوان**: 25 محاولة دخول كحد أقصى / 5 دقائق لكل IP (يمنع تعداد المستخدمين)
  - رسالة الرفض موحّدة دائماً («بيانات الدخول غير صحيحة») — لا كشف هل اسم المستخدم موجود أم لا

#### V4: كلمة المرور الافتراضية للإدارة (G4) — ⚠️ إجراء مطلوب منك
- **الوصف**: حساب الإدارة يعمل بـ `admin/admin123` المعروف ومذكور في وثائق المشروع — إن لم تُغيَّر فهو باب مفتوح
  لكل من قرأ هذه الوثائق.
- **تم إنجازه برمجياً**:
  - تبويب جديد «الأمان والحسابات» في لوحة الإدارة يعرض **تنبيهاً أحمر** ما دامت الكلمة الافتراضية مستخدمة
  - نموذج تغيير كلمة المرور (كلمة حالية + جديدة + تأكيد) مع مقياس قوة حي
  - سياسة جديدة: 8 أحرف على الأقل + حرف إنجليزي + رقم، والجديدة يجب أن تختلف عن الحالية
  - تغيير كلمة مرور مكاتب الفروع متاح أيضاً من «إعدادات الفرع» في حساب كل مكتب، والإدارة تستطيع إعادة
    تعيين أي كلمة مكتب من تبويب الفروع (مع إبطال جلساته فوراً)
- **المطلوب منك**: تسجيل الدخول → الأمان والحسابات → تغيير كلمة المرور الآن. *(اختبار G4 سيصبح أخضر بعد ذلك)*

### 🟡 متوسطة — تم الإصلاح

#### V5: تسريب بيانات المنخرطين عبر استعلام الحالة (F1)
- **الوصف**: `/api/public/enroll-status` كان يكشف (الاسم الكامل + الفرع + حالة الطلب) **بإدخال رقم الهاتف وحده** —
  يمكن تجربة أرقام هواتف عشوائية لتعداد منخرطين.
- **الإصلاح**: الاستعلام يتطلب الآن **الهاتف + اللقب معاً** (مطابقة حرفية)، ومن لا يجمع الاثنين يحصل على نتيجة
  فارغة دائماً. أُضيف حقل «اللقب (كما في الطلب)» لبطاقة التتبع بثلاث لغات + حد 10 استعلامات/10 دقائق لكل عنوان.

#### V6: غياب ترويسات حماية HTTP (G1)
- **الوصف**: الردود كانت بلا ترويسات أمان → قابلية تخمين نوع المحتوى وتسريب معلومات بيئة التشغيل.
- **الإصلاح** (تُرسل مع كل رد من `next.config.ts`):
  - `X-Content-Type-Options: nosniff`
  - `Referrer-Policy: strict-origin-when-cross-origin`
  - `Permissions-Policy: camera=(), microphone=(), geolocation=(), payment=(), usb=(), interest-cohort=()`
  - `Strict-Transport-Security` (يفرض HTTPS عند النشر الحقيقي)
  - ملاحظة: عمداً لا يوجد `X-Frame-Options: DENY` لأن المعاينة تعمل داخل iframe — والمحتوى الحساس محمي بالتوكن.

#### V7: إغراق النماذج العامة
- **الوصف**: نموذج الانخراط/الاتصال/المتجر كانت تُقبل طلبات بلا حدود → إغراق قاعدة البيانات وصندوق الرسائل.
- **الإصلاح**: حد 8 طلبات / 10 دقائق لكل عنوان لكل نموذج + رسالة عربية واضحة مع مدة الانتظار.

#### V8: حقول بلا حد أقصى للطول (E5)
- **الوصف**: عناوين الأخبار وأسماء اللاعبين كانت تقبل حمولات ضخمة (اختُبر 200KB) → تخزين معلن وإغراق.
- **الإصلاح**: حدود طول صارمة على كل حقول المكدس (عنوان 200، محتوى 20,000، أسماء 100، روابط 600...).

### 🟢 منخفضة — تم الإصلاح

#### V9: مدة جلسة طويلة
- الجلسات كانت أسبوعاً كاملاً → قُلصت إلى **24 ساعة** (متزامنة مع الكوكي والتوكن) مع إبطال فوري عند التغيير.

## 3) نقاط القوة التي اجتازت الفحص منذ البداية

| المحور | النتيجة | التفصيل |
|---|---|---|
| حقن SQL (E1/E2) | ✅ | Prisma ORM باستعلامات مُعاملة — محاولات `' OR 1=1 --` و`DROP TABLE` رُفضت ببساطة |
| XSS المخزّن (E3) | ✅ | React يهرّب كل النصوص تلقائياً؛ لا `dangerouslySetInnerHTML` إلا لنص ثابت (تهيئة الثيم) |
| الإسناد الجماعي (E4) | ✅ | zod يهمل الحقول الزائدة: حقن `status/age/isAdmin/createdAt` لم يغيّر شيئاً |
| عزل الفروع (C1/C2/C4) | ✅ | كل استعلامات المكتب مقيّدة بـ `branchId` من الجلسة — تعديل/حذف بيانات فرع آخر مستحيل |
| فصل الأدوار (B6/B7) | ✅ | دور الجلسة مخزّن بالتوكن الموقّع ويتحقق منه الخادم في كل طلب |
| توقيع التوكن (B4/B5/B8) | ✅ | مقارنة زمنية ثابتة `timingSafeEqual`، رفض `alg=none`، رفض المنتهي |
| كلمات المرور (G3) | ✅ | scrypt (ذاكرة-صعبة) + ملح عشوائي 16بايت لكل حساب + مقارنة زمنية ثابتة |
| الكوكي (G2) | ✅ | `HttpOnly` + `SameSite=Lax` (يمنع CSRF الفعلي للطلبات المتقاطعة) |
| رسائل الأخطاء | ✅ | عامة بلا تفاصيل مكدس أو نسخ قاعدة بيانات |

## 4) بنية الحماية الحالية (دفاعات متعددة الطبقات)

```
الطبقة 1 — التحقق من الهوية
├─ كلمات مرور scrypt + ملح عشوائي + مقارنة زمنية ثابتة
├─ قفل مؤقت بعد 5 إخفاقات (10 دقائق) + حد 25 محاولة/5 دقائق لكل IP
├─ سياسة كلمة مرور: 8+ أحرف، حرف + رقم
└─ تنبيه حي في لوحة الإدارة ما دامت الكلمة الافتراضية مستخدمة

الطبقة 2 — الجلسات
├─ توكن موقّع HMAC-SHA256 بمفتاح من بيئة التشغيل (لا قيم افتراضية — fail-closed)
├─ مدة 24 ساعة
├─ إبطال فوري لكل الجلسات عند تغيير كلمة المرور (tokenInvalidBefore + iat)
└─ كوكي HttpOnly + SameSite=Lax احتياطي، وترويسة Bearer للتطبيقات

الطبقة 3 — التخويل
├─ دور في التوكن (office/admin) + فحص خادمي في كل مسار
├─ عزل بيانات الفروع بـ branchId على مستوى كل استعلام (ضد IDOR)
└─ 401 فوري لأي وصول بلا جلسة صالحة — مسجل في السجل الأمني

الطبقة 4 — التحقق من المدخلات
├─ zod على كل نقطة دخول (أنواع، أطوال قصوى، أنماط هاتف/تاريخ)
├─ العمر والحالة يُحسبان خادمياً فقط (ضد التلاعب)
└─ Prisma معاملات — لا SQL خام نهائياً

الطبقة 5 — حدود المعدل ومضادة الإساءة
├─ تسجيل دخول: قفل حساب + حد عنوان
├─ النماذج العامة: 8/10 دقائق لكل IP
├─ استعلام الحالة: 10/10 دقائق لكل IP + يتطلب هاتف + لقب
└─ حدود طول الحقول ضد الحمولات الضخمة

الطبقة 6 — الترويسات والتدقيق
├─ nosniff / Referrer-Policy / Permissions-Policy / HSTS
├─ سجل أحداث أمنية في قاعدة البيانات (آخر 100 حدث في لوحة الإدارة)
└─ مراقبة حية: دخول ناجح/فاشل، أقفال، تجاوز حدود، تغييرات كلمات المرور
```

## 5) سجل الأحداث الأمنية (جديد)

تُسجَّل تلقائياً في قاعدة البيانات وتُعرض في **الإدارة العامة → الأمان والحسابات**:

| نوع الحدث | متى يُسجل |
|---|---|
| دخول ناجح | كل دخول مكتب فرع أو إدارة (مع IP) |
| محاولة دخول فاشلة | كل كلمة مرور خاطئة (مع اسم المستخدم المستهدف وIP) |
| قفل حساب مؤقت | عند تفعيل القفل بعد الإخفاقات المتكررة |
| تجاوز حد الطلبات | عند حجب عنوان بسبب الإغراق |
| تغيير كلمة مرور | تغيير ذاتي للإدارة أو للمكتب |
| إعادة تعيين كلمة مرور | إعادة تعيين من الإدارة لحساب مكتب |

*ملاحظة خصوصية: لا يُخزَّن أي محتوى حساس في السجل — أسماء مستخدمين وعناوين IP ووصف عام فقط.*

## 6) ما الذي يبقى مسؤولية النشر (خارج بيئة التطوير الحالية)

1. **HTTPS إلزامي**: فعّل شهادة TLS عند النشر على دومين حقيقي (ترويسة HSTS جاهزة).
2. **تغيير كلمة مرور الإدارة** ⚠️ — الإجراء الأهم المتبقي: من اللوحة → الأمان والحسابات.
3. **نسخ احتياطي دوري** لملف `db/custom.db` (النسخ الاحتياطي جزء أساسي من أي استراتيجية حماية).
4. **تحديثات الحزم** الدورية (`bun update`) للحفاظ على تصحيحات الأمان.
5. **AUTH_SECRET**: عند نقل المشروع لخادم إنتاج، أنشئ مفتاحاً جديداً هناك ولا تعيد استخدام مفتاح التطوير
   (`openssl rand -hex 32`).

## 7) إعادة تشغيل اختبار الاختراق

```bash
bun run scripts/pentest.ts
```

يعمل السكربت 34 اختباراً ضد `http://localhost:3000` ويطبع تقريراً فورياً بالنتائج، وينظف بياناته التجريبية
بنفسه (كل ما يُنشئه يحمل الوسم `_pentest_`). ملاحظة: يستهلك اختبار القوة الغاشمة 15 محاولة دخول، لذا انتظر
5 دقائق أو أعد تشغيل الخادم قبل إعادة الفحص (حدود المعدل في الذاكرة).
